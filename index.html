03 Opinions

Opinions, strongly held

Mostly about Swift. All of them negotiable, except number two.

  1. SwiftUI is the architecture.

    Views draw the screen. Presenters own navigation, sheets and alerts. State lives in observable objects in the environment. There are no view models.

  2. Never force-unwrap an optional.

    Ever. If a value can be nil, the code should say what happens when it is.

  3. Write the prototype like it’s shipping.

    Because it will. Nearly every prototype I’ve been asked to build ended up in production.

  4. Previews are part of the product.

    Every SwiftUI preview should build and show real data. If you’re going to use the new tools, use them properly.

  5. Own your handle.

    Build on protocols no single company controls, and make your identity a domain you own. Mine is this one.

The long version is my skills repo, the Swift conventions I give coding agents so their code reads like mine.
